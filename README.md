# freelens-teleport-extension

Teleport Kubernetes clusters in the Freelens catalog, with the `tsh proxy kube` local proxy managed for you.

> **Written by AI.** The code, the tests and this README were generated by an AI assistant from a one-line request. Read it as such.

## What it does

Every Kubernetes cluster your Teleport session can see appears in the Freelens catalog, refreshed every minute from `tsh kube ls`. Opening one starts `tsh proxy kube` for it on a fixed local port, or reuses the proxy already listening there; a proxy left over from a previous login is stopped and replaced. With no Teleport session, or an expired one, Freelens shows a notification with the `tsh login` command to run in a terminal: the extension never logs in for you.

## Requirements

Freelens 1.10.x and `tsh`, logged in at least once. On Linux and macOS, Freelens imports the PATH of your login shell, so `tsh` only has to work in a terminal; on Windows it must be on the Windows PATH (user or system), not one set only in a shell profile. No `kubectl` needed: the extension uses the one bundled with Freelens, or the "Path to kubectl binary" preference when set.

## Install

In Freelens, open Extensions, paste the URL of the `.tgz` asset from the [latest release](https://github.com/baptisterajaut/freelens-teleport-extension/releases/latest), and install. Then restart Freelens: on a fresh install Freelens 1.10 can loop enabling and disabling an extension ([freelensapp/freelens#1005](https://github.com/freelensapp/freelens/issues/1005)), and a restart settles it.

Upgrading in place can race with the removal of the previous version and leave an empty extension. If that happens: quit Freelens, delete `~/.freelens/extensions/freelens-teleport-extension`, start Freelens, install the new `.tgz`.

## Sharing proxies with your shell

The port of a cluster is `18000 + cksum(name) % 1000`, with the POSIX `cksum`. A shell helper using the same formula reuses the extension's proxies, and the other way round:

```sh
port=$((18000 + $(printf '%s' "$cluster" | cksum | cut -d' ' -f1) % 1000))
tsh proxy kube "$cluster" -p "$port"
```

Two cluster names can land on the same port. The extension then reports the port as held by another proxy and leaves it alone.

## Troubleshooting

Each proxy logs to `~/.tsh/freelens-teleport-<cluster>.log` (`%USERPROFILE%\.tsh` on Windows, `$TSH_HOME` when set). Behind a TLS-intercepting corporate proxy, `tsh` needs `TELEPORT_TLS_ROUTING_CONN_UPGRADE=yes`: the extension sets it unless the variable is already defined.

## Platforms

Tested on Linux. macOS should work and is not tested yet. The Windows code paths are written and have never run.
